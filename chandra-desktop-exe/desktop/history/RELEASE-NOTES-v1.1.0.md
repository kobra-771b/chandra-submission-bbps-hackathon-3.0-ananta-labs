# Chandra Desktop v1.1.0 — the Engine release

- **Removed the live screen-mirror.** The Computer page's "View screen" window streamed the real display over the local bridge about once a second, a continuous screenshare running in the background. It is gone: the button, the window, the 0.9-second polling loop, and its dead markup and CSS. The single, approval-gated screenshot Chandra takes only when you ask it to read the screen is unchanged, and Take over and Lock still work.

- **Undo.** Chandra now reverses her own last file change — a write, a move, or a trashed delete — on request ("undo"). It costs nothing at rest: a short, session-only list in the host, never written to disk. No approval is needed to undo, since it only restores something already approved once.
- **One memory, not two.** Remembering something now always lands in the same place the Memory page shows, whichever way it was said — a direct "remember that..." or something Chandra decides to note mid-task. A new recall_memory tool lets her search everything remembered, not just what's already in the conversation.

- **Extra tools with MCP.** Chandra can use any MCP tool server (browser, GitHub, files, search, memory). Copy `mcp.example.json` to `mcp.json` in Chandra's data folder and press Reload tools in Settings. Each server needs your approval in an on-screen dialog before it first starts, each tool asks in the chat before it runs, and the results are treated as data. Chandra's file tools can no longer read or edit Chandra's own data folder (key, settings, tool list).

- **Chandra's personality is yours to write.** Settings > Chandra's personality holds Chandra's voice and character (default: warm, quick, a little dry, honest about what Chandra doesn't know). It saves to persona.md in Chandra's data folder and applies from Chandra's next reply. Reset restores the default.
- **Opening apps on Windows works.** "Open my file explorer", notepad, calculator, settings and Start-menu apps are found by name; if one can't be found, Chandra says so instead of Windows showing an error box.

- **Lite mode for older computers.** It turns on by itself on a machine with 4 cores or 4 GB of RAM or less, and Settings has a switch to force it on or off (it reloads the window). Lite skips the WebGL background, the per-card glass filters and the blur, and starts with music off. In a headless test the idle CPU cost fell about tenfold (5.7 s to 0.5 s over 8 s) and the first load from 1.3 s to 0.2 s, with the same look.
- **A much smaller page.** The ambient loop is now a 0.65 MB mono file the host serves on demand (it was 2 MB of stereo embedded in the page), and the logo is stored once as WebP. The app file went from 3.7 MB to 0.6 MB.

- **One assistant, no workspace.** The Agent Workspace, its right-edge persona agents, their settings, the spawn/message tools and the custom endpoint are gone. Chandra's chat is the only assistant: it plans, uses Chandra's tools, reads the results and answers in one reply. Risky actions ask inside the chat (Allow once, Always allow, Deny, Stop). Quick local commands ("open spotify", "set volume 40") still run at once. The computer bridge moved to Settings > Computer bridge. Keys live only in chandra.env (an old browser copy of a key is removed on first launch).

- **One place for the key.** Settings > AI brain takes the Claude key and writes it to `chandra.env` in Chandra's data folder, through the host (never kept in the window). Remove key clears it. A key left in an older build's window moves to `chandra.env` on first launch and is removed from the window.
- **No key in the app.** The Claude key that 1.0.x embedded (obfuscated) in the page is gone. The page now asks Chandra's own host (`/brain`), and the host reads `ANTHROPIC_API_KEY` from `chandra.env` on this computer. A key typed into Settings still works and goes direct. CI now fails the build if a key appears in the source.
- **The Chandra Engine.** With no Claude key, Chandra thinks with the Chandra Engine: OpenJarvis's local, OpenAI-compatible server on this computer (`CHANDRA_ENGINE_URL`, default `http://127.0.0.1:8000`). Private, free, offline. Screen reading still needs Claude, and says so plainly instead of guessing.
- **Agent Workspace preset: "Chandra Engine (this computer)".** One click points an agent at the engine through the host's `/engine/v1` proxy (pairing code required; screenshots are reduced to a text note, because the local model reads text only).
- **What you allowed in onboarding now counts.** With "Keyboard & Mouse" on, the Agent Workspace opens apps, pages and windows (`open_app`, `open_url`, `focus_window`) without a per-step prompt, and its log says which permission allowed it. Clicks, typing, files and shell still ask in the default mode; "Approve every step" still asks for everything; turning the permission off in Settings brings the prompt back at once (permission switches now save the moment they change).
- **One installer for everything.** `Chandra-Setup.exe` (about 14 MB, per-user, no admin) installs Chandra Desktop with its own trimmed Python runtime, plus Chandra's setup, face, engine bridge and the engine's source; the Start menu's **Set up Chandra** opens the guided setup. Built on macOS or Linux by `installer/build_installer.sh`. Uninstalling removes exactly what Setup installed, never your data, key, notes, or Chandra's other pieces.
- **`chandra.env` choices:** `CHANDRA_BRAIN=auto|claude|engine`, `CHANDRA_ENGINE_MODEL`. See `chandra.env.example`.
- **One version everywhere.** App, window chrome, settings footer, Windows version resource, NSIS installer and CI all read 1.1.0. The Inno Setup definition is retired (NSIS since 1.0.5); CI now builds with NSIS too, from the repository root.
- **Part of Chandra.** Chandra Desktop now ships inside the Chandra toolbox beside Chandra's memory, voice, face and engine; `start.sh desktop` / `start.bat desktop` starts the engine's server and then this window.

Unchanged: black-only UI, eclipse arc and liquid blobs, frameless window with traffic lights, per-action approval for real mouse and keyboard control, pairing code, loopback binding, the corner failsafe, and Stop all.

Build outputs: `Chandra.exe` and `Chandra-Setup-v1.1.0.exe`, compiled on Windows (see `docs/BUILD.md`).
